# منظومة برنامج حُفّاظ السُّنة

منظومة التسجيل والامتحانات والشهادات: تسجيل الطلبة في مستويات البرنامج، مراجعة الطلبات وإحالتها للمحكّمين، تحديد المواعيد وإشعار الطلبة، إجراء الامتحان أونلاين مع احتساب الدرجة لحظياً وفق **الدليل الاسترشادي لآلية التحكيم**، اعتماد النتائج على مرحلتين، وإصدار شهادات برقم ورمز QR قابل للتحقق العام.

**التقنيات:** React 19 · Vite 8 · React Router 8 · TanStack Query 5 · Supabase (Postgres + Auth + RLS + Edge Functions + Storage)

- الموقع المنشور: <https://hoffadasona-source.github.io/hussas-system/>
- خارطة الطريق: [ROADMAP.md](ROADMAP.md) · الملخص التقني الكامل: [docs/SYSTEM_CONTEXT.md](docs/SYSTEM_CONTEXT.md)

---

## المزايا الأساسية

- **برنامج مستمر بلا دورات:** التسجيل يُفتح ويُغلق من الإعدادات، والطالب يتدرّج في المستويات من الأول إلى الخامس.
- **الطلبة السابقون:** التعرّف على الطالب بالرقم الوطني وتاريخ الميلاد، وتعبئة بياناته تلقائياً، وعرض مستوياته السابقة، ومنع إعادة امتحان مستوى اجتازه.
- **أساس التحكيم في صفحة واحدة:** معايير التقييم · الخصميات بكسور الدليل (¼ · ½ · 1) · سلّم التقديرات · نص الدليل الاسترشادي، مع محاكاة مباشرة للدرجة.
- **قاعة امتحان أونلاين:** بطاقات خصم بالعدد، تراجع متعدد الخطوات، حفظ تلقائي، ووضع عرض فقط بعد الإرسال.
- **شهادات بقالب حر:** رفع قالب PDF أو صورة وتحديد مواضع الحقول بالسحب، أو استعمال التصميم المدمج، مع رمز QR للتحقق.
- **هوية قابلة للضبط:** شعار الجهة وحجمه من الإعدادات، ويظهر فوراً في الموقع العام ولوحات التحكم.
- **إشعارات:** طابور رسائل آلي مع تذكير قبل الموعد، وتصدير Excel/CSV للإرسال عبر نظام محلي، وتحديد جماعي كـ«مُرسلة».
- **أسماء مستخدمين عربية:** الدخول باسم مثل «عبدالرحيم أحمد شيتة»، وكلمة المرور التي يضعها الإداري نهائية.

## التشغيل محلياً

المتطلبات: Node.js 22.6 أو أحدث، Docker Desktop، Supabase CLI.

```bash
npm install
```

```bash
npx supabase start
```

انسخ `.env.example` إلى `.env.local` وضع فيه `API URL` و`anon key` و`service_role key` المطبوعة، ثم:

```bash
npm run create-admin -- "مصطفى الهادي" "كلمة-مرور-قوية" "مصطفى الهادي"
```

```bash
npm run dev
```

- الموقع العام: <http://localhost:5173>
- لوحة الإدارة: <http://localhost:5173/admin/login> · لوحة المحفّظ: <http://localhost:5173/examiner/login>

لإعادة بناء قاعدة البيانات من الصفر: `npm run db:reset` · ولتطبيق الترحيلات الجديدة فقط: `npx supabase migration up --local`.

## النشر

**قاعدة البيانات (Supabase السحابي)**

```bash
npx supabase link --project-ref YOUR-PROJECT-REF
```

```bash
npx supabase db push
```

```bash
npx supabase secrets set USERNAME_EMAIL_DOMAIN=users.hussas.local ALLOWED_ORIGIN=https://your-domain CRON_SECRET=قيمة-عشوائية
```

```bash
npm run functions:deploy
```

من لوحة Supabase: **Authentication → Sign In / Providers** عطّل *Allow new users to sign up* (الحسابات من لوحة الإدارة فقط).

**الواجهة (GitHub Pages — مضبوطة آلياً)**

كل دفعة إلى `main` تبني الواجهة وتنشرها عبر `.github/workflows/pages.yml`، مع `VITE_BASE=/<اسم المستودع>/` ومتغيري `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` من **Settings → Secrets and variables → Actions → Variables**. ملف `404.html` يُولَّد آلياً لدعم الروابط المباشرة.

> `SUPABASE_SERVICE_ROLE_KEY` لا يوضع في الواجهة ولا في متغيرات النشر أبداً — يُستعمل فقط في سكربتات جهازك.

## الأدوار والصلاحيات

| الدور | ما يستطيعه |
|---|---|
| مدير النظام | كل شيء: الإعدادات، أساس التحكيم، المستخدمون، الإشعارات، إلغاء الشهادات، إعادة فتح النتائج المعتمدة، استيراد المكاتب |
| إداري | مراجعة الطلبات وقبولها ورفضها، التحويل للمحكّمين، المواعيد، المحفّظون، التقارير وسجل العمليات والإشعارات. الاعتماد النهائي وإصدار الشهادات **بصلاحية فردية** |
| محفّظ (محكّم) | طلابه المحالون إليه فقط: المواعيد، إجراء الامتحان، اعتماد المحفّظ |
| الزائر | التسجيل، متابعة الطلب، الاستعلام عن النتيجة المعتمدة، التحقق من الشهادة |

الصلاحيات مفروضة في قاعدة البيانات نفسها (RLS + إجراءات `security definer` + صلاحيات أعمدة + عروض `security_invoker`)، لا في الواجهة فقط. كل تغيير حالة يمر عبر إجراء يتحقق من الصلاحية ويكتب في `audit_log`.

**تحديد المعدل:** 60 استعلاماً و30 تسجيلاً لكل عنوان IP كل 10 دقائق (الموظفون مستثنون). و**جلب بيانات الطالب السابق** يتطلب الرقم الوطني وتاريخ الميلاد معاً للزائر، فلا تُكشف بيانات التواصل بمعرفة الرقم الوطني وحده.

## مسار العمل

```
الطالب يسجّل ─► pending ─► under_review ─► approved ─► assigned (إحالة لمحكّم)
   ─► scheduled (موعد + إشعار) ─► in_exam (جلسة أونلاين، حفظ تلقائي)
   ─► admin_pending (اعتماد المحكّم) ─► published (اعتماد الإدارة، تظهر النتيجة)
   ─► إصدار الشهادة (CERT-YYYY-00001 + QR)
فروع: rejected · absent · postponed · إرجاع النتيجة للمحكّم مع السبب
```

قواعد البرنامج المستمر: طلب مفتوح واحد لكل طالب، ولا يُعاد امتحان مستوى حالته «منشورة».

## قاعدة احتساب الدرجة

```
درجة السؤال = الأساس − Σ (الدرجة القصوى للمعيار − الممنوحة) × معامل المعيار − Σ (عدد مرات الخصم × قيمته)
النتيجة النهائية = متوسط الأسئلة (أو أقل درجة) ÷ الأساس × 100، محصورة بين 0 و100
```

مثال بمقياس الدليل (أساس السؤال 20): الصوت والأداء 7 من 10 بمعامل 0.4، وتنبيه ×1 (1)، ولحن خفي ×2 (0.25) ← 20 − 1.2 − 1 − 0.5 = **17.3 من 20 (86.5%)**.

- الحساب بأعداد صحيحة في الخادم (`compute_question_score`) والواجهة (`src/lib/scoring.js`) معاً، فتتطابق كسور الدليل والكسر المئوي تماماً. الخادم هو المرجع.
- عند بدء الجلسة تُحفظ **لقطة** من الإعدادات والمعايير والخصميات داخل الامتحان، فلا يتأثر امتحان سابق بأي تعديل لاحق.

## الإشعارات

تُضاف الرسائل إلى الطابور تلقائياً عند: استلام الطلب، قبوله أو رفضه، تحديد الموعد أو تغييره، التذكير قبله (24 ساعة وساعتين افتراضياً بتوقيت ليبيا)، اعتماد النتيجة، وصدور الشهادة. تغيير الموعد أو الغياب يلغي ما لم يُرسل.

**الوضع الحالي — الإرسال المحلي:** من صفحة «الإشعارات» اضغط *تصدير المعلقة Excel/CSV* لتنزيل ملف بأعمدة (رقم الهاتف الدولي · نص الرسالة · الاسم · رقم الطلب · النوع)، أرسلها من نظامك المحلي، ثم حدّد الرسائل واضغط *تحديد كمُرسلة*.

**للإرسال الآلي:** اربط قناة بأسرار Edge Functions (`WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID`، أو `SMS_API_*`، أو `RESEND_API_KEY`)، وشغّل `supabase/snippets/schedule-send-messages.sql` مرة واحدة، ثم فعّل الإشعارات من **الإعدادات ← الإشعارات**.

## ملاحظات للمطوّرين

- لا يُعدَّل ملف migration منشور؛ يُضاف ملف جديد `YYYYMMDDHHMMSS_وصف.sql`.
- أي عرض (View) جديد: أعد ضبط الصلاحيات بعده، لأن مخطط `public` في Supabase يمنح anon/authenticated كل الصلاحيات افتراضياً — و`npm run test:usage` يكشف ذلك.
- تعديل قاعدة الدرجات يكون في SQL و`src/lib/scoring.js` معاً، ثم `npm run test:scoring`.
- النصوص عربية، والتواريخ بتوقيت `Africa/Tripoli`، والتصميم من متغيرات `global.css` ويعمل على الهاتف وفي الوضع الليلي.
