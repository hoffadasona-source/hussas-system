# منظومة برنامج حُفّاظ السُّنة

منظومة التسجيل والامتحانات والشهادات: تسجيل الطلبة، مراجعة الطلبات وإحالتها للمحفّظين، تحديد المواعيد وإشعار الطلبة، إجراء الامتحان أونلاين مع احتساب الدرجة لحظياً، اعتماد النتائج على مرحلتين، إصدار شهادات برقم ورمز QR قابل للتحقق، وإشعارات آلية عبر واتساب أو SMS أو البريد.

**التقنيات:** React 19 · Vite 8 · React Router 8 · TanStack Query 5 · Supabase (Postgres + Auth + RLS + Edge Functions + pg_cron)

خارطة الطريق الكاملة في [ROADMAP.md](ROADMAP.md).

## التشغيل محلياً

المتطلبات: Node.js 22.6 أو أحدث، Docker Desktop (يعمل)، Supabase CLI.

```bash
npm install
```

```bash
npx supabase start
```

يطبع الأمر السابق `API URL` و `anon key` و `service_role key`. انسخ `.env.example` إلى `.env.local` وضع القيم فيه، ثم:

```bash
npx supabase functions serve
```

```bash
npm run create-admin -- admin "كلمة-مرور-قوية" "مصطفى الهادي"
```

```bash
npm run dev
```

- الموقع العام: http://localhost:5173
- لوحة الإدارة: http://localhost:5173/admin/login
- لوحة المحفّظ: http://localhost:5173/examiner/login
- Supabase Studio: http://127.0.0.1:54323

لإعادة بناء قاعدة البيانات من الصفر بعد تعديل ملفات migrations: `npm run db:reset`.

## النشر على Supabase السحابي

1. أنشئ مشروعاً في [supabase.com](https://supabase.com) (يفضّل منطقة Frankfurt).
2. من **Authentication → Sign In / Providers**: عطّل **Allow new users to sign up** (الحسابات تُنشأ من لوحة الإدارة فقط).
3. اربط المشروع وارفع قاعدة البيانات:

```bash
npx supabase link --project-ref YOUR-PROJECT-REF
```

```bash
npx supabase db push
```

4. اضبط الأسرار وانشر الدالتين:

```bash
npx supabase secrets set USERNAME_EMAIL_DOMAIN=users.hussas.local ALLOWED_ORIGIN=https://your-domain.ly CRON_SECRET=قيمة-عشوائية-طويلة
```

```bash
npm run functions:deploy
```

5. أنشئ أول مدير نظام من جهازك (بعد وضع `VITE_SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` للمشروع السحابي في `.env.local`):

```bash
npm run create-admin -- admin "كلمة-مرور-قوية" "اسم مدير النظام"
```

6. انشر الواجهة على Vercel أو Netlify أو Cloudflare Pages:
   - أمر البناء `npm run build`، ومجلد الإخراج `dist`.
   - متغيرات البيئة: `VITE_SUPABASE_URL`، `VITE_SUPABASE_ANON_KEY`، `VITE_USERNAME_EMAIL_DOMAIN`.
   - توجيه كل المسارات إلى `index.html` مضبوط مسبقاً في `vercel.json` و `public/_redirects`.
   - **لا تضع** `SUPABASE_SERVICE_ROLE_KEY` في إعدادات الاستضافة.
7. في Supabase: **Authentication → URL Configuration** ضع رابط الموقع في Site URL.

## الإشعارات الآلية

تُضاف الرسائل إلى طابور في قاعدة البيانات تلقائياً عند: استلام الطلب، قبوله أو رفضه، تحديد الموعد أو تغييره، التذكير قبل الموعد (افتراضياً قبل 24 ساعة وقبل ساعتين)، اعتماد النتيجة، وصدور الشهادة. تغيير الموعد أو إلغاؤه أو تسجيل الغياب يُلغي التذكيرات التي لم تُرسل. الدالة `send-messages` ترسل المستحق، وتعيد المحاولة مرتين عند الفشل.

الإشعارات **معطّلة افتراضياً**. لتفعيلها:

1. اربط قناة واحدة على الأقل بأسرار Edge Functions:

| القناة | الأسرار |
|---|---|
| واتساب (WhatsApp Cloud API) | `WHATSAPP_TOKEN`، `WHATSAPP_PHONE_NUMBER_ID`، واختيارياً `WHATSAPP_TEMPLATE_LANG` (الافتراضي `ar`) و `WHATSAPP_API_VERSION` |
| رسائل SMS | `SMS_API_URL`، `SMS_API_KEY`، `SMS_SENDER` (مزود عام يستقبل JSON؛ عدّل `_shared/messaging.ts` حسب المزود المعتمد) |
| البريد (Resend) | `RESEND_API_KEY`، `EMAIL_FROM` |

2. شغّل `supabase/snippets/schedule-send-messages.sql` مرة واحدة من SQL Editor (بعد استبدال رابط المشروع وقيمة `CRON_SECRET`) ليُرسَل المستحق كل دقيقة.
3. من **الإعدادات ← الإشعارات**: فعّل الإشعارات، واختر القناة، واكتب رابط الموقع العام، ثم أرسل رسالة تجريبية.
4. **واتساب:** الرسالة الأولى لأي طالب يجب أن تكون قالباً معتمداً من Meta. أنشئ القوالب في WhatsApp Manager، ثم اكتب اسم كل قالب وترتيب متغيراته في محرر القوالب داخل المنظومة.

سجل كل الرسائل وحالتها وإعادة إرسال الفاشل منها في صفحة **الرسائل**. زر «إرسال عبر واتساب» اليدوي يبقى متاحاً دائماً.

## استيراد طلبات قائمة

لترحيل طلبات مسجّلة في Excel: احفظ الملف بصيغة **CSV UTF-8** بنفس أعمدة `scripts/import-template.csv`، ثم افحصه أولاً دون إنشاء أي طلب:

```bash
npm run import -- data.csv --user admin --password "كلمة-المرور" --dry-run
```

ثم نفّذ الاستيراد (يمكن تحديد الدورة بـ `--cycle "اسم الدورة"`):

```bash
npm run import -- data.csv --user admin --password "كلمة-المرور"
```

- يقبل الفاصلة أو الفاصلة المنقوطة، والتواريخ بصيغة `2006-05-10` أو `10/05/2006`، والأرقام العربية.
- يطابق أسماء المكاتب والمستويات والمتون مع تجاهل التشكيل واختلاف الهمزات والتاء المربوطة.
- يكتب تقريراً `data.result.csv` فيه رقم الطلب لكل صف أو سبب رفضه.
- كل طلب يمر بنفس تحقق التسجيل العادي ويُسجَّل في سجل العمليات باسم الحساب المستخدم.

## الأدوار والصلاحيات

| الدور | ما يستطيعه |
|---|---|
| مدير النظام | كل شيء، بما فيه الإعدادات والمعايير والخصميات والمستخدمون والإشعارات، وإلغاء الشهادات وإعادة فتح النتائج المعتمدة |
| إداري | مراجعة الطلبات وقبولها ورفضها، التحويل للمحفّظين، المواعيد، المحفّظون، التقارير وسجل العمليات والرسائل. الاعتماد النهائي وإصدار الشهادات **بصلاحية فردية** |
| محفّظ | طلابه المحالون إليه فقط: تحديد المواعيد، إجراء الامتحان، اعتماد المحفّظ |
| الزائر | التسجيل، متابعة الطلب، الاستعلام عن النتيجة المعتمدة، التحقق من الشهادة |

الصلاحيات مفروضة في قاعدة البيانات نفسها (RLS + إجراءات `security definer` + صلاحيات أعمدة)، لا في الواجهة فقط؛ فلا يمكن تجاوزها باستدعاء الـ API مباشرة. إضافة إلى ذلك:

- **كلمة المرور المؤقتة:** كل حساب تنشئه الإدارة أو تعيد تعيين كلمة مروره يُلزم بتعيين كلمة مرور جديدة عند أول دخول.
- **تحديد المعدل:** الاستعلامات العامة والتسجيل محدودة لكل عنوان IP (60 استعلاماً و30 تسجيلاً كل 10 دقائق). الحدود سخية لأن شبكات الهاتف تشارك العناوين بين مستخدمين كثيرين.

## مسار العمل

```
الطالب يسجّل ─► pending ─► under_review ─► approved ─► assigned (إحالة لمحفّظ)
   ─► scheduled (موعد + إشعار) ─► in_exam (جلسة أونلاين، حفظ تلقائي)
   ─► admin_pending (اعتماد المحفّظ) ─► published (اعتماد الإدارة، تظهر النتيجة)
   ─► إصدار الشهادة (CERT-YYYY-00001 + QR)
فروع: rejected · absent · postponed · إرجاع النتيجة للمحفّظ مع السبب
```

## قاعدة احتساب الدرجة

```
درجة السؤال = الأساس − Σ (الدرجة القصوى للمعيار − الممنوحة) × معامل المعيار − Σ (عدد مرات الخصم × قيمته)
النتيجة النهائية = متوسط الأسئلة (أو أقل درجة) ÷ الأساس × 100، محصورة بين 0 و100
```

مثال بالإعدادات الافتراضية: الصوت 7 من 10 (معامل 2)، تنبيه ×1 (6)، لحن خفي ×2 (1.5) ← 100 − 6 − 6 − 3 = **85**.

- تُحتسب الدرجة في الواجهة لحظياً (`src/lib/scoring.js`) وتُعاد على الخادم عند كل حفظ وعند الإرسال (`compute_question_score`)، والخادم هو المرجع.
- عند بدء الجلسة تُحفظ **لقطة** من الإعدادات والمعايير والخصميات داخل الامتحان، فلا يتأثر أي امتحان سابق بتعديل لاحق.

## حالة التحقق

- **منجز ومختبر:** كل الاختبارات أعلاه ناجحة ما عدا `test:e2e`، و`npm run build` ناجح، وجُرّبت صفحات الإدارة وقاعة الامتحان ونموذج التسجيل وإعدادات الإشعارات وتغيير كلمة المرور في المتصفح بعرض الهاتف ببيانات تجريبية.
- **لم يُشغَّل بعد:** `npm run test:e2e` على Supabase حقيقي (Docker Desktop على جهاز التطوير لم يعمل)، ولا Edge Functions على Deno فعلياً، ولا الإرسال عبر مزود حقيقي لعدم وجود مفاتيح. هذه أول مهام المرحلة الأولى في خارطة الطريق.
